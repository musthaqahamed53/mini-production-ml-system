# Customer Churn Prediction — Production ML System (Option A)

End-to-end, leak-free production Machine Learning system for **Customer Churn Prediction** on imbalanced subscriber data, engineered to satisfy Level 4 ML Model Engineering standards.

## Serialized Artifacts (`artifacts/`)

- `.gitkeep`: Preserves the `artifacts/` directory in version control; generated binaries and plots can be ignored when appropriate.
- `churn_pipeline.joblib`: Fitted Scikit-Learn `Pipeline` combining preprocessing (`ColumnTransformer`) and the tuned LightGBM classifier.
- `fallback_pipeline.joblib`: Fitted fallback pipeline combining preprocessing with `DummyClassifier(strategy="prior")`, used when primary model inference fails.
- `threshold_config.json`: Stores the optimal probability threshold, business-cost parameters (`cost_fn`, `cost_fp`), tuned model metadata, hyperparameters, and risk-tier boundaries.
- `metrics_report.json`: Evaluation metrics for Dummy, Logistic Regression, and tuned LightGBM across validation and test data, including cost-related results.
- `pr_curve.png`, `confusion_matrix.png`, `threshold_cost_curve.png`: Diagnostic plots generated by `src/evaluate.py`.

## Setup & Reproducible Execution

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt

# macOS LightGBM may require the OpenMP runtime
brew install libomp

# 1. Fetch and verify the dataset
python data/fetch_data.py

# 2. Train models, optimize the cost threshold, and serialize artifacts
python -m src.train

# 3. Evaluate the held-out test set and generate plots/report
python -m src.evaluate

# 4. Run drift simulation and alert checks
python -m src.drift_monitor

# 5. Start the FastAPI service
uvicorn serving.app:app --host 127.0.0.1 --port 8000

# 6. In another terminal, run batch scoring
python -m serving.predict_batch --input-csv data/telco_churn.csv --output-csv artifacts/batch_predictions.csv

# 7. Run the combined API latency and batch-throughput benchmark (250+ requests)
# Start the service first, then run in another terminal:
python -m serving.benchmark --url http://127.0.0.1:8000 --requests 250

# Load-test options: use 250, 500, or 1000 measured API requests
python -m serving.benchmark --url http://127.0.0.1:8000 --requests 500

# The report includes p50/p95/p99 latency, HTTP status counts, API throughput,
# and batch scoring throughput. The minimum supported request count is 200.

# 8. Run the automated test suite
pytest -v
```
